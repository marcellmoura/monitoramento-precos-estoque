# US-10 — Corrigir dados extraídos antes da confirmação

## Descrição

Como usuário autorizado da loja, quero corrigir dados extraídos incorretamente, para validar preços e apresentações antes de incorporá-los.

## Classificação

| Campo | Valor |
|---|---|
| Tipo | História de usuário |
| Épico | Importação e Conferência |
| Escopo | MVP obrigatório |
| Prioridade | Alta |
| Status inicial | Backlog |
| Estimativa | A definir |
| Responsável previsto | marcellmoura |
| Perfis autorizados | Administrador, Compras |
| Fase / marco | P7 / E2 |
| Referências | RF05, RF06 |
| Testes / evidências | T04, T06 |
| Depende de | US-09, US-34 |
| Especificação e pré-requisitos | D05, D07 |

## Critérios de aceitação

- [ ] Administrador/Compras corrigem/complementam campos extraídos antes da confirmação e verificam unidade/embalagem/coluna.
- [ ] Revalidar após correção e manter pendência quando inválido ou não associado.
- [ ] Preservar origem e ator, sem sobrescrever histórico; correção posterior segue US-35.
- [ ] Permitir corrigir os itens restantes de importação parcialmente confirmada sem duplicar os já validados.

## Condições de conclusão

- Atender aos critérios de aceitação e executar os testes pertinentes.
- Aplicar a definição de pronto do índice `docs/backlog.md`.
- Registrar evidências de build, testes e revisão; atualizar documentação e status somente conforme o trabalho realizado.
