# TT-05 — Automatizar testes das regras, endpoints e fluxos

## Descrição

Construir testes incrementais que comprovem regras e previnam regressões.

## Critérios de aceitação

- [ ] Implementar testes junto de cada funcionalidade; esta tarefa consolida a suíte, não adia testes para o final.
- [ ] Cobrir aumento, redução, igualdade, novo, preço zero e associação pendente obrigatoriamente.
- [ ] Cobrir testes HTTP de corpo/status/validação/erro, regras isoladas, parser, persistência, frontend e fluxo integrado proporcional ao risco.
- [ ] Cobrir duplicidade, falha parcial, código repetido, embalagem diferente, ausências e reentrada.
- [ ] Relatar testes executados e falhas; não substituir comportamento por cobertura percentual.

- [ ] Testar permissões por perfil, campos sensíveis, sessões/CSRF, correções, retroativos, confirmação parcial e processamento interrompido conforme AP01–AP19.

## Condições de conclusão

- Atender aos critérios de aceitação e executar os testes pertinentes.
- Aplicar a definição de pronto do índice `docs/backlog.md`.
- Registrar evidências de build, testes e revisão; atualizar documentação e status somente conforme o trabalho realizado.
