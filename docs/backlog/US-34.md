# US-34 — Restringir funções e dados por perfil

## Descrição

Como usuário, quero acessar apenas ações e dados autorizados à minha função para preservar a separação de responsabilidades.

## Classificação

| Campo | Valor |
|---|---|
| Tipo | História de usuário |
| Épico | Usuários e Acesso |
| Escopo | MVP estendido |
| Prioridade | Alta |
| Status inicial | Backlog |
| Estimativa | A definir |
| Responsável previsto | marcellmoura |
| Perfis autorizados | Todos, conforme matriz |
| Fase / marco | P3a e transversal |
| Referências | AP15; AP01; AP18 |
| Testes / evidências | Matriz HTTP/campos/frontend |
| Depende de | US-29 |
| Especificação e pré-requisitos | AP01–AP20 em docs/decisoes.md; detalhar contratos antes da implementação |

## Critérios de aceitação

- [ ] Implementar matriz AP15 na API e adaptar navegação/ações no React.
- [ ] Administrador acessa tudo; Compras opera cadastros/importação/correção/referência e consulta sugestões, sem administrar usuários/margens ou venda posterior.
- [ ] Compras informa venda inicial no cadastro; posteriormente só Administrador edita venda.
- [ ] Estoque consulta identificação/quantidades e ajusta estoques/acompanha reposição, sem custos/importações.
- [ ] Consulta lê catálogo/venda/disponibilidade, sem alterações/custos. Filtrar campos em respostas, não apenas esconder na tela.
- [ ] Negar acesso direto indevido a PDFs, dados e operações; sem sessão 401, sem permissão 403; testar por perfil.

## Condições de conclusão

- Atender aos critérios de aceitação e executar os testes pertinentes.
- Aplicar a definição de pronto do índice `docs/backlog.md`.
- Registrar evidências de build, testes e revisão; atualizar documentação e status somente conforme o trabalho realizado.
