# US-21 — Tratar preços inválidos e itens não identificados

## Descrição

Como usuário autorizado da loja, quero identificar preços inválidos e itens não reconhecidos, para evitar registros e comparações incorretos.

## Classificação

| Campo | Valor |
|---|---|
| Tipo | História de usuário |
| Épico | Importação e Conferência |
| Escopo | MVP obrigatório |
| Prioridade | Alta |

| Fase / marco | P7–P8 / E2 |

| Testes / evidências | T05, T06 |
| Depende de | US-09, US-34 |
| Especificação e pré-requisitos | D06, D08 |

## Critérios de aceitação

- [ ] Sinalizar preço importado zero, negativo ou ausente como inválido/pendente e informar motivo.
- [ ] Não transformar vazio em zero válido; só dados válidos/associados entram no histórico.
- [ ] Identificação insuficiente ou não associada permanece pendente; nome parecido só sugere associação.
- [ ] Correção revalida o item sem duplicar confirmados; confirmar parcialmente os válidos quando aplicável.

## Condições de conclusão

- Atender aos critérios de aceitação e executar os testes pertinentes.
- Aplicar a definição de pronto do índice `docs/backlog.md`.
- Registrar evidências de build, testes e revisão; atualizar documentação e status somente conforme o trabalho realizado.
