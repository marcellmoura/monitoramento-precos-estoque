# US-31 — Administrar usuários e perfis

## Descrição

Como Administrador, quero cadastrar e administrar usuários para atribuir acesso conforme função.

## Classificação

| Campo | Valor |
|---|---|
| Tipo | História de usuário |
| Épico | Usuários e Acesso |
| Escopo | MVP estendido |
| Prioridade | Alta |
| Status inicial | Backlog |
| Estimativa | A definir |
| Responsável previsto | marcellmoura |
| Perfis autorizados | Administrador |
| Fase / marco | P3a |
| Referências | AP15–AP16 |
| Testes / evidências | CRUD permitido e último admin |
| Depende de | US-29 |
| Especificação e pré-requisitos | AP01–AP20 em docs/decisoes.md; detalhar contratos antes da implementação |

## Critérios de aceitação

- [ ] Cadastrar nome, e-mail único, um perfil e senha temporária; sem cadastro público.
- [ ] Perfis Administrador/Compras/Estoque/Consulta conforme matriz AP15, sem autoelevação de privilégio.
- [ ] Permitir mudar perfil/ativar/desativar, invalidando sessões aplicáveis.
- [ ] Impedir desativação ou rebaixamento do último Administrador ativo; testar inclusive solicitações concorrentes.
- [ ] Guardar senha como hash Argon2id; não retornar hash/senha em consultas.

## Condições de conclusão

- Atender aos critérios de aceitação e executar os testes pertinentes.
- Aplicar a definição de pronto do índice `docs/backlog.md`.
- Registrar evidências de build, testes e revisão; atualizar documentação e status somente conforme o trabalho realizado.
